# Контракт файлов для Phaser / React

## Папки

```text
art/source/                          исходники генерации, без перезаписи
  P01-lobby-v01.png
  P02-player-v01.png
  ...
art/review/                          контактные листы, превью, GIF
apps/web/public/assets/generated/    только готовые ассеты
tools/art/                          скрипты обработки
docs/art/ASSET_PROVENANCE.json        происхождение и проверки
```

Версии raw-источников сохранять как `v01`, `v02`. В runtime — одно согласованное имя. Не добавлять даты и случайные суффиксы к runtime-именам.

## Порядок кадров персонажей

Индекс слева направо, затем следующая строка; **без промежутков и полей между кадрами**:

| Индекс | Анимация | Требование |
|---:|---|---|
| 0 | idle A | Спокойная базовая стойка |
| 1 | idle B | Маленькое дыхание, ноги не смещаются |
| 2 | run A | Левая нога впереди |
| 3 | run B | Проходная поза |
| 4 | run C | Правая нога впереди |
| 5 | run D | Проходная поза |
| 6 | hit | Короткая реакция, без нарисованной вспышки |
| 7 | down | Поваленная фигура, без крови |

Для 48×48: ступни базовых кадров на y≈42, центр корпуса x≈24. Высота фигуры около 34–40 px. Для босса 64×64: ступни y≈57, центр x≈32. Всё содержимое с запасом минимум 2px до края. Анимация не должна менять одежду, лицо, оружие, масштаб и угол камеры между кадрами.

Тень не запекать в спрайт: её рисует игра. Не генерировать muzzle flash/урон/цифры поверх тела — эффекты идут отдельно из pixelfx.

## Нормализация

1. Сохранить исходник как есть.
2. Проверить, действительно ли есть alpha, или это нарисованная шахматка.
3. При плохой сетке извлечь позы в отдельные изображения; не резать вслепую по равным ячейкам.
4. Убрать фон, не уничтожив тёмный контур персонажа. При сомнительном alpha — перегенерировать на однотонном фоне, который не встречается в одежде.
5. Сохранять пропорции, один масштаб для всех кадров одного персонажа; выровнять опорную точку.
6. Уменьшить nearest-neighbor до целевых ячеек. Если это выглядит как грязная россыпь пикселей, перегенерировать упрощённую графику. Не прятать дефекты blur-фильтром.
7. Собрать атлас в указанный размер.
8. Открыть лист при 1× и 4×. Проверить прозрачность, контуры и движение.

Не требуется делать runtime-анимации из лобби: это статичная иллюстрация, небольшое движение добавляет основной агент.

## Проверка перед передачей

- Все имена, размеры и число кадров соответствуют таблице.
- Нужные файлы имеют прозрачные пиксели по краям и непрозрачное тело.
- Нет подписей, сетки, водяных знаков и нарисованного фона у предметов.
- Асфальт и тротуар смотрятся без шва в превью 3×3.
- Персонажи читаются на #080B10, #141B25 и игровом асфальте.
- Нельзя принять идентичный кадр восемь раз за готовую анимацию.
- Контактные листы и проверки указаны в ASSET_STATUS.md.
- Все готовые пути перечислены в INTEGRATION_NOTES.md.
