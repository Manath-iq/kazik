# Мобильные исправления — 05.11.2026

## Причины и изменения

1. Нижняя `.game-hint` занимала 31,5 CSS px в исходном браузерном замере. Убрана из игровой разметки; инструкции остаются в лобби и доступном имени игрового поля. Canvas подгоняется под весь остаток высоты через ResizeObserver, без прежнего ограничения 400–900 logical px. Снизу остаётся только системный safe area.
2. Наземные пропы были просто картинками. Теперь у машины footprint по корпусу, у ограды — по основанию, у фонаря/бака — компактные основания. Движение по осям с малыми swept-подшагами не пробивает тонкую ограду на рывке и позволяет скользить вдоль края. Те же коллизии у врагов; локальные waypoint-обходы препятствий без дорогого поиска пути каждый кадр. Снаряды проверяют сегмент пути и останавливаются препятствием. Разметка и подвесной неон не блокируют движение. Глубина наземных объектов обновляется по позиции ног 10 раз/с.
3. Все пары 72 мобов давали 2 556 проверок каждый кадр. Пространственные buckets сокращают круг кандидатов; плотная клетка имеет бюджет до 12 проверяемых пар на моба, с ротацией порядка. Broadphase попаданий не имеет такого лимита: попадания не пропускаются ради FPS. Тени теперь используют одну маленькую текстуру вместо отдельной геометрической Ellipse под каждым мобом. VFX ≤12, плавающий текст ≤12 переиспользуется, лут ≤240, массивы уплотняются на месте. Анимации невидимых мобов приостановлены, логика движения остаётся. Пауза/фон усыпляют Phaser loop, возобновление пробуждает его. Количество врагов (72), баланс и шансы выпадений не урезаны.
4. Старый магнит использовал `distance × 12` px/с: при скорости героя 155 px/с предмет зависал примерно в 12,9 px, дальше порога подбора 12 px; на максимальных кроссовках — ещё дальше. Теперь захват постоянный, скорость минимум max(360, 1,8×speed), с ускорением до 720 px/с. Добыча не отцепляется за радиусом, подбирается по пройденному шагу без остановки. Деньги/опыт начисляются ровно один раз; звук/вибрация и всплывающие суммы объединяются, а не создаются пачкой на каждый предмет.

## Сопоставимые браузерные прогоны

Chromium OpenCode на Mac, viewport **344×751**, локальная DEV review-сцена, фиксированный seed 20261105 и 72 моба, 240 RAF-кадров. Это **не** замер физического телефона.

| Метрика | До | После |
| --- | ---: | ---: |
| Медиана RAF | 16,7 ms | 16,7 ms |
| p95 | 18,3 ms | 17,5 ms |
| p99 | 18,6 ms | 17,6 ms |
| Кадры >33,4 ms | 0/240 | 0/240 |
| Canvas | 1 | 1 |
| Проверки разделения на последнем кадре | 2 556 (по коду) | 676 (runtime) |

CPU-профили сохранены инструментом Browser: исходный 10,4 с, новый 16,0 с. Длительности неодинаковы, сырые selfMs напрямую не сравниваются. В исходном профиле заметны `batchTri` (87,8 ms) и `FillPathWebGL` (30,8 ms); после замены теней они не входят в top-12. Исходный Mac уже выдерживал частоту около 60Hz — эти цифры не доказывают устранение лагов на конкретном iPhone/Android. Нужен повторный плейтест пользователя на том же телефоне.

## Проверки

- Unit: корпус/скольжение/диагональ/тонкая ограда/выход из препятствия, обход врагом, swept-снаряд, магнит на 15/30/60/120 FPS с максимальной скоростью, захват за границей радиуса, spatial query и budget.
- Локальные E2E: реальные WASD держатся в корпусе машины, canvas заполняет высоту, магнит на движущемся герое, crowd=72 и ограниченное число display objects. В review-сцене нет API/наград. Она подключается только в DEV, production bundle её не содержит.
- Настоящие устройство, Telegram fullscreen и длительный прогон на тяжёлых волнах ещё требуют проверки владельцем.
