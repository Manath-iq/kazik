# Безопасность и границы перед публичным запуском

## Реализовано

- Telegram HMAC-SHA256 через Web Crypto verify, auth_date с TTL и запретом будущих дат; проверка дублирующихся полей.
- Случайные серверные сессии; в БД хранится SHA-256 токена, TTL 2 часа; в браузере только память.
- Local auth вынесен в отдельный entry и не импортируется production bundle.
- Все приватные действия проверяют сессию/владельца. JSON body limit 20KB, схемы Zod, POST rate limit 90/мин.
- Кошелёк: append-only ledger, уникальные refs, trigger + CHECK, атомарные D1 batches. CAS для финализации раундов/забегов/сборов, версии blackjack.
- Криптографический RNG с rejection sampling (без modulo bias); сервер хранит скрытые данные crash/blackjack.
- Webhook secret сравнивается timing-safe. Для команд — dedupe update_id, для платежей — уникальный charge ID и атомарная D1 запись **до** HTTP 200. Финансовые события не теряются из-за старого dedupe команд.
- Stars: серверная цена/валюта/плательщик/версия согласия, ограничение invoice-спама, CAS pre-checkout/refund, неизменяемая identity платежа, история только плательщику. Client invoiceClosed не подтверждает оплату. Никаких проводок Stars в игровой wallet_ledger.
- Полный self-service возврат только исходному плательщику, pending при неизвестном сетевом исходе; refunded webhook и повторный refund восстанавливают состояние. Выключение приёма не отключает учёт старых платежей/возвраты. /terms /support /paysupport ведут к владельцу.
- Проверки подозрительных вылазок и исключение из выплат/рейтинга.

## Ещё не решено / не обещаем

1. **Нет полного античита:** Phaser-клиент можно модифицировать. Достоверность топовых рекордов требует replay/server verification. `guarded` не значит «честность доказана».
2. **Pre-auth DoS/квоты:** rate limit игрока не защищает от anonymous auth requests и массовой регистрации валидных Telegram аккаунтов. Перед публичным продвижением добавить IP/request throttling на уровне платформы; это не заменяется Turnstile на каждом игровом действии.
3. **Потерянная отправка бота:** update_id резервируется до sendMessage, поэтому при сетевом сбое ответ может не дойти. Автоповтор не создаёт деньги, но нужна отдельная outbox/retry-механика для надёжности сообщений.
4. **Резервное копирование/удаление данных:** политика retention и процедура удаления Telegram-профиля ещё не реализованы. Платёжные записи нельзя чистить вместе с временными сессиями/дедупом. Перед расширением приёма Stars владелец должен обеспечить регулярный защищённый экспорт D1 и проверить восстановление. Checkpoints и игровые истории со временем требуют архива/очистки в рамках бесплатной D1.
5. **Ручной Telegram QA:** реальные iOS/Android WebView, серверные задержки и сетевые потери не заменяются Chromium smoke-тестами.
6. **Правила платформы/закон:** не проведена юридическая проверка виртуального казино и публичного распространения по регионам/возрасту.
7. **Секреты:** по прямому решению пользователя переданный тестовый Bot Token установлен только в изолированном тестовом Worker; он не используется в исходниках/клиентской сборке. Webhook и меню подключены. Для будущего публичного бота использовать отдельные секреты; тестовую авторизацию не считать production-релизом.

## Что проверяют тесты

API тесты выполняются в отдельной временной D1, без remote-флагов/секретов. Проверяются подпись/срок авторизации, права, отсутствие production dev login, отрицательные ставки, конкурентные покупки/сборы/cashout/finish/hit, однократные выплаты, blackjack natural/bust/timeout, скрытые карты и crash point, работы, бизнес-лимит, бандовые вклады/cooldown и неизменяемость ledger.

Браузерные тесты используют только локальный dev-сервер и его локальную БД. Они не доказывают защищённость публичной инфраструктуры и не являются аудитом независимого специалиста.
